# CS60055 Challenge 2 — Cross-Room Few-Shot WiFi CSI Activity Recognition

Python pipeline from raw CSI captures (Room A: Nexmon BCM4366c0 `.pcap`, Room B: amplitude `.csv`)
to (150, 256) amplitude windows, self-supervised representations, and cross-room few-shot
activity recognition.

## Setup

```bash
python3 -m venv ~/.venvs/ubi2 && source ~/.venvs/ubi2/bin/activate
pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu   # CPU build
pip install -r requirements.txt
```

Use a fresh venv: scikit-learn imports pandas if present, and an old pandas built against
numpy 1.x crashes under numpy 2.x. pandas is not needed by this project.

Place the dataset (never committed) as:

```
raw/experiment2/realdata/input_data/30ms/csidata/{fall,sit,sitdown,stand,standup,walk,validation/...}/*.pcap
raw/experiment3/Data/*.csv
```

Only the capture files and ReadMe PDFs are needed; the source authors' code is not used.

## Data preparation

```bash
python scripts/inspect_data.py    # source-file facts -> results/inspection.json, results/figures/
python scripts/build_dataset.py   # raw -> intermediate_csv/ -> QC -> windows/ (~7 min on 12 cores)
python -m pytest tests -q         # decoder, QC, windowing and split-isolation checks
```

| Stage | Module | What it does |
|---|---|---|
| PCAP reading | `src/pcap_reader.py` | UDP/5500 payloads, Nexmon 18-byte header, rejects malformed packets |
| CSI decoding | `src/csi_decode.py` | 4366c0 block-float words → complex CSI → amplitude, frequency order |
| Common form | `src/intermediate.py` | one CSV per capture, `subcarrier_001..256`, rows in record order |
| Quality control | `src/cleaning.py` | rejects non-finite, all-zero, duplicate and partial-band observations |
| Splits | `src/splits.py` | Room A: supplied `validation/`; Room B: 25/class, lexicographic sort + `default_rng(42)`, frozen in `splits/room_B_validation.txt` |
| Windowing | `src/windowing.py` | each capture's valid sequence resampled to 150 steps (polyphase, anti-aliased) |
| Normalization | `src/normalization.py` | per-window median gain removal, log, per-subcarrier z-score fitted on development only |

Settings live in `configs/experiment.yaml`; the `preprocessing` section is hashed into every
window's provenance record.

### Key data facts and design decisions

- **Room A mixes 20 MHz and 80 MHz frames.** ~71% of observations carry energy only in the
  primary 20 MHz sub-band (192 subcarriers at noise floor). The minimum sub-band energy share is
  cleanly bimodal (`results/figures/subband_energy_share.png`); QC keeps observations with share
  ≥ 0.005. This leaves a median of 59 full-band observations per Room-A capture vs ~499 in Room B.
- **One window per capture, by resampling.** Since no Room-A capture has 150 full-band
  observations, every capture's valid sequence (both rooms) is resampled to 150 steps. Padding
  was rejected because it would give the room classifier a trivial cue.
- **Exclusions.** Captures with < 10 valid observations cannot form a window: 7 Room-A
  development and 2 Room-A validation captures (`sit201`, `stand137`). Room-A validation
  therefore has 148 of 150 captures. See `results/qc_report.json`.
- Packet record order is kept as temporal order (2 captures show small timestamp reversals).

### Provenance

`windows/index.csv` maps each `window_XXXX.npy` to its split, capture, source file, source
SHA-1, number of valid observations and preprocessing config hash. Window ids are a seeded
permutation and carry no room/label information. `splits/captures.csv` holds per-capture QC counts.

## Experiments and inference

```bash
python scripts/task1_room.py              # room identification + window-length study (~13 min)
python scripts/task2_ssl.py               # SimCLR encoder, linear probes, UMAP (~13 min)
python scripts/task3_fewshot.py           # few-shot A<->B, K=1/5/10/20, ablations (~1.5 h, CPU)
python scripts/task3_fewshot.py --plot-only   # redraw Task-3 figures from saved episodes
python scripts/task3_improvements.py      # targeted fixes for the diagnosed failure modes (~10 min)
python run_episode.py EPISODE_DIR --out predictions.csv   # window_id, room, label, confidence
```

Results land in `results/` (`task1_room.csv`, `task2_ssl.csv`, `task3_fewshot.csv`,
`task3_per_class_K5.csv`, `figures/`, `predictions/`). The technical report draft is
`report/report.md`; demo notes are in `report/demo_notes.md`.
